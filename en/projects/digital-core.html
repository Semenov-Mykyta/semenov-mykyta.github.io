    Overview

    Digital Core automates order handling for a one-person digital-goods shop on an online marketplace. When an order is paid, the system checks it, delivers the product from local stock or buys it from an external supplier, and messages the buyer. The goal was to reduce repetitive manual work while guarding against two costly mistakes: delivering an order twice, or paying a supplier for an order that has since been refunded.

    Architecture

    A core application provides shared services: persistent storage, the marketplace connection, a journal of external actions, order finalization and listing automation. Business features are separate plugins built on these services: delivery of unique items from local stock, purchasing from external suppliers with routing between several of them, and per-product settings.

    Paid orders arrive as real-time events. A periodic reconciliation job is designed to pick up orders that were missed, for example after a restart, so processing does not depend on a single event arriving.

    The design uses the action journal to track external operations such as supplier purchases and deliveries, and to support investigation when their outcome is uncertain. In that case the documented behaviour is to stop the order for manual review instead of retrying automatically. The system serves one owner on one server and is controlled through a Telegram bot. Rather than adding a message broker, a second database or distributed locks, the plugins reuse the core's storage and per-order locks.

    My Contribution

    I defined requirements, coordinated AI-assisted implementation and separate independent reviews, and assessed changes against acceptance criteria. AI tools generated the implementation code; my role focused on specification, testing oversight and acceptance decisions.

    Results

    The repository documents concrete defects that were found and fixed, several with dedicated regression tests. A stock counter could be marked as verified even when the storage transaction around it was rolled back; it is now marked only after the commit succeeds. Periodic reconciliation started its own broad marketplace sync, duplicating traffic; it now reuses the core's order cache. A feature that had widened one plugin's scope by mistake was removed again.
